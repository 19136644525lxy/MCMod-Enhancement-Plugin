# MC百科 UI 现状诊断与重构方向

> 分析日期：2026-11-10
> 素材：首页 HTML（182KB）+ 全站 CSS（82.5KB，9 个文件）
> 说明：物品页/模组页样本因站点间歇性断连暂未取得，相关结论基于此前抓取过的结构记录，标注为「待样本确认」。

## 1. 现状：一份 2010 年代的技术债清单

从 CSS 统计里能直接读出来的事实：

| 维度 | 现状 | 问题 |
| --- | --- | --- |
| 正文字号 | `12px`（17 处），14px 29 处 | 12px 在 1080P/2K 下偏小，长文阅读累 |
| 字体 | `"Microsoft YaHei"` 全局 | 可接受，但无字重层级、无衬线/等宽搭配 |
| 断行 | `word-break: break-all` | 中文会在任意字间断开，出现「模/组」这类拆词 |
| 链接色 | `#06c`（老式蓝），hover 变黑+下划线 | 视觉噪音大，不像 2020 年代的产品 |
| 蓝色体系 | `#06c` / `#5490e9` / `#2575f9` 三种蓝并存 | 主色不统一，按钮和链接观感割裂 |
| 灰阶 | `#222 #333 #555 #888 #999 #aaa #ccc #ddd #eee #f9f9f9` 十级 | 层级过多，实际用不出区别 |
| 圆角 | `5px` 为主（32 处），另有 3/10/40/2px | 5px 是典型的「半圆不圆」年代 |
| 阴影 | 全站仅 14 处 `box-shadow` | 卡片没有浮起感，全靠边框 |
| 光标 | 自定义 `arrow.png` / `hand.png` | 已被现代浏览器视为过时做法，且影响触控 |
| 顶栏 | `#3d454c` 深灰蓝，高 49px | 2010 年代「深色工具条」审美 |
| 布局 | `.main{width:1200px}` + `float` + 绝对定位 | 无响应式，窄屏/大屏都不适配 |
| 图片 | gif/png sprite 切圆角、做背景 | 高清屏模糊，且难换肤 |

## 2. 五个具体病灶

### 2.1 字号与密度：只有「小」和「更小」
12px 正文 + 大量 14px 辅助 + 22px 标题，中间缺 16/18 的过渡层。首页一屏塞了 15 个区块，每个区块又塞 10 张卡，信息密度接近门户网站，但缺少「呼吸」。
现代内容站的常见节奏是：正文 15–16px / 行高 1.6–1.75，辅助 13px，标题 24–32px，区块间距 32–48px。

### 2.2 色彩没有语义
十级灰阶 + 三种蓝，意味着「强调」只能靠加粗和蓝链接。没有「成功/警告/危险」的语义色，没有「主色 12% 淡底」这类派生规则，标签、按钮、提示各用各的颜色。

### 2.3 层级靠边框，不靠空间
卡片用 `1px solid #ccc/#ddd` 分隔，圆角 5px，几乎没有阴影。结果是一屏全是框线，视觉噪音大，读者分不清「哪些是一组」。
现代做法：用留白分组、用浅色底分区、用阴影/描边二选一，而不是全靠边框。

### 2.4 布局是「固定宽度 + 浮动」
`.main{width:1200px}`、`.news_block{width:1154px;float:left}`、`.class_block .left{width:907px;float:left}`、`.blcok_frame{position:absolute;top:35px}`。
这是 2010 年 PC 站的标准解法，代价是：小屏横向滚动、大屏两侧大片空白、任何结构调整都要改像素。

### 2.5 信息架构：首页是「所有东西都放一点」
首页 15 个块：导航、banner、公告、模组卡、操作入口、统计、编辑动态、教程、社群动态、最受欢迎、版本检索、热门标签、贡献榜……
每个块都想被看见，结果是没有主次。用户打开首页的目的通常是：**找一个模组 / 看新收录 / 查一个物品**，而不是浏览 15 个栏目。

## 3. 重构原则

按你的要求：**功能一个不少，UI 可以重制**。落地时建议守三条：

1. **先视觉、后结构**：第一版只换 token（颜色/字号/圆角/阴影/间距）+ 重排现有容器，不动 DOM 结构和链接。风险最低，可随时回滚。
2. **保 SEO 与路由**：所有链接仍是原生 `<a href>`，分页/筛选仍是 GET 参数，不做前端路由。
3. **渐进式**：按页面类型逐个上线（首页 → 搜索页 → 物品页 → 模组页），每类页面独立开关。

## 4. 页面骨架重构建议

### 4.1 首页
现状：15 个平铺块。
建议：**三层结构**
- 第一层「找东西」：搜索框 + 版本/加载器快捷筛选 + 热门标签
- 第二层「看内容」：模组卡（保留 3 个 tab：随便看看/最新收录/有新动态）+ 教程卡
- 第三层「社区与数据」：编辑动态、社群动态、贡献榜、统计——折叠或降级为侧栏

### 4.2 物品页（待样本确认）
现状：左侧合成表/用途，右侧属性，底部评论。
建议：**双栏 + 粘性目录**
- 左：物品图标、名称、ID、来源模组（主信息卡）
- 中：合成表、用途、获取方式（分节，可锚点跳转）
- 右：属性表、标签、相关物品
- 评论区保持原样（写操作不接管）

### 4.3 模组页（待样本确认）
现状：简介 + 内容列表 + 评论区，长页面。
建议：**顶部概览卡 + 粘性子导航**（简介/物品/教程/评论），内容区单栏 720–800px 阅读宽度。

### 4.4 搜索页
现状：`.result-item` 列表，标题 + 摘要 + 元信息。
建议：**结果卡 + 类型筛选 chips**（模组/整合包/资料/教程/作者/用户/社群），卡片内显示类型徽标、快照时间、来源；空结果给「去结构化检索」的出口。

### 4.5 列表页（modlist / modpack）
现状：卡片网格，信息量固定。
建议：**网格 + 密度切换**（舒适/紧凑），卡片支持封面、名称、英文名、简介两行截断。

## 5. 设计 token 方向（学习 MARGIN 的思路，不是抄皮肤）

MARGIN 值得学的是「一套克制的 token」，具体数值可以按 MC 百科的内容气质重定：

| 维度 | 建议 |
| --- | --- |
| 底色 | 暖白 `#f7f6f3`（不是纯白，减少刺眼）；深色 `#141416` |
| 表面 | `#fff` / 深色 `#1c1c1f` |
| 文字 | 主 `#1a1a1a`、次 `#5f6167`、弱 `#8a8b90` |
| 主色 | 保留百科绿或改用一个沉稳的蓝绿，只保留**一个**主色 |
| 语义色 | 成功/警告/危险各一个，且都有 12% 淡底版本 |
| 字号 | 正文 15px / 行高 1.7；辅助 13px；标题 24/20/17 三档 |
| 圆角 | 基准 12px，卡片 12、按钮 8、chip 999 |
| 阴影 | 两级即可：`0 1px 2px / 0 8px 24px`，用暖色阴影 |
| 间距 | 4/8/12/16/24/32/48 的 8 点栅格 |
| 动效 | 150–250ms，`cubic-bezier(.22,1,.36,1)`；只用于 hover/展开 |

## 6. 实施路径

1. **Phase 0（1 天）**：把上面的 token 写成 `tokens.css`，在现有页面上做「只换颜色/字号/圆角，不动布局」的灰度版本，截图对比。
2. **Phase 1（2–3 天）**：首页重排——把 15 块收敛成 3 层，先只调容器顺序和间距，不动内部。
3. **Phase 2（3–4 天）**：搜索页 + 列表页重绘（这两类结构最干净，风险最低）。
4. **Phase 3（3–5 天）**：物品页/模组页双栏重排。
5. **Phase 4**：打磨（暗色、响应式、动效、无障碍）。

> 每一步都可以用插件开关单独回滚，不 push 到线上站点。
