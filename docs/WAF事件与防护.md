## 排查结论

- 故障期间全站（www / bbs / search / play）均不可达，切换 DNS、指定不同 WAF 节点（103.236.70.180、103.248.154.126、43.240.73.19、43.254.166.30）均无法稳定访问。
- 海外在线工具访问返回 200，站点本身存活；手机流量（不同出口）同样失败，排除单一出口 IP 被封。
- 结论：站点 WAF 侧对「高频访问同一资源」做了限制，用户 IP 被判定为异常流量来源。

## 插件代码审计

对 `src/` 全量检索后确认：

- 无 `createElement('img')`、无 `new Image`、无 `img.src =` 赋值；
- 全部 CSS 无 `url(...)`（无背景图、无字体、无光标图片）；
- 唯一的 `fetch` 在 `src/bg.js:26`，由命令面板触发，目标只有两种页面：
  - `https://search.mcmod.cn/s?key=…`
  - `https://www.mcmod.cn/modlist.html?key=…`
- 唯一的 `createElement('link')` 在 `src/content/core/theme.js:13`，用于注入样式表。

**即：插件没有任何会请求图片的代码路径。**

## 可能原因（未完全证实）

- 调试首页排版期间（11-10 18:30–18:55）反复手动刷新首页，每次刷新都会重新请求首页的图片资源；单张 banner 图在多次刷新中被累计请求上千次，与站长日志吻合。
- 插件本身不请求图片，但页面刷新 + 浏览器缓存策略会让同一张图反复回源。

## 已加的防护

1. **白名单收紧**（`src/bg.js`）：只允许三类 URL，其余一律拒绝：
   - `search.mcmod.cn/s?…`
   - `www.mcmod.cn/modlist.html?…`
   - `www.mcmod.cn/(item|class|post)/数字.html`
2. **滑动窗口限流**：60 秒内最多 30 次真实请求，超出返回 `RATE_LIMITED`。
3. **请求计数**：`mp:stats` 消息返回 `fetched` / `blocked` / `cache`，调试面板中显示「网络请求 N 次（拦截 M）」。
4. **命令面板最小长度**：单字不触发请求，避免宽泛搜索放大请求量。
5. 所有请求结果缓存 5 分钟（bg 层 40 条、content 层 30 条）。

## 后续建议

- 观察 1–2 天，若 WAF 不再触发，说明防护有效。
- 若再次触发，先停用插件做对照；同时在调试面板查看「网络请求」计数是否异常增长。
- 向站长说明：插件只做页面重排与本地搜索面板，不会抓取图片；如仍有异常，可提供具体图片 URL 进一步定位。
