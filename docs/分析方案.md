# MC百科全站增强插件 · 分析与实施方案

> 版本：v0.2（已按"完全重绘 + Cmd+K 优先"调整）
> 日期：2026-11-10
> 参考对象：MARGIN（B站增强插件，MV3）

---

## 0. 结论摘要

1. MC百科是**传统 PHP 服务端直出**站点，没有 SPA、没有公开 API。数据全在 HTML 里，可直接 `fetch` + `DOMParser` 解析。
2. 全站页面归为 **6 类**：资料页（class/item）、文章页（post）、整合包页（modpack）、检索页（modlist/modpack.html）、工具页（tools/rank/history）、社区页（bbs/play）。
3. 搜索有**两个互不相通的入口**：`search.mcmod.cn/s?key=`（全文）与 `www.mcmod.cn/modlist.html`（结构化筛选）。这是插件最值得填补的空白。
4. **视觉路线定为"完全重绘"（MARGIN 式）**：插件不再做覆盖式美化，而是接管展示层、自绘 UI。这决定了架构必须是「**抽取层 → 数据模型 → 渲染层**」三段式，而不是 CSS 覆盖。
5. 重绘的最大风险不是工作量，而是**原生交互失效**（编辑、评论、评分、上传都绑定在原 DOM 上）。对策是"三类分区 + 失败回退"（见 3.3）。

### 1.2 搜索系统

**入口 A：全文搜索 `search.mcmod.cn/s`**

- 参数：`key`、`filter`（结果类型，0 = 全部）、`page`（实测可达 82 页）
- 结果项结构：
  ```
  .result-item
    .head   > .class-category > ul > li > a.c_{分类id}   // 分类角标
            > a[href=/class/{id}.html]                    // 标题
    .body   > 摘要文本（含 [ban:title_menu][h1=简介] 等编辑语法残留）
    .foot   > .info > .value  // 地址、快照时间、来源
  ```
- 特点：**有"快照时间"字段**（站内索引快照，非实时库）；摘要残留 wiki 语法，说明预处理弱。

**入口 B：结构化检索 `www.mcmod.cn/modlist.html`**

- 参数：`mcver`（1.21.1/1.20.1/1.18.2/1.16.5/1.12.2/1.7.10…）、`category`、`sort`（createtime/lastedittime）、`api`（1/2，加载器）、`key`、`page`
- 结果卡结构：`.item-table-hover` > `.ename` / `.name` / `.intro` / `.intro-content` / `.intro-button` / `.cover`
- 特点：筛选维度齐全，但**只支持单选组合，筛选状态不跨页保持**。

**两个入口互不相通**：搜索结果不带版本/加载器；检索结果不带全文相关度。→ 这正是 Cmd+K 聚合面板的价值所在。

### 1.3 数据可得性

- 无公开 JSON API（`/api/` 返回 404）。
- 数据全在 HTML，服务端直出，`fetch` + `DOMParser` 即可解析，无需执行 JS。
- 匿名请求无强反爬（本次测试 20+ 次全部正常），但不代表可滥用——插件应低频、按需、带缓存。

### 1.4 技术栈特征

- PHP 模板 + jQuery（`data-toggle="tooltip"`、`data-original-title"` 等 Bootstrap 3 痕迹）。
- 大量 `table` 布局（物品页 12 个表）。
- tab 容器用**纯数字 id**（`id="1"`、`id="2"`），选择器需 `[id="1"]` 或改用 class。
- 静态资源走 `//www.mcmod.cn/static/...` 与 `i.mcmod.cn` CDN。
- 非 SPA → 不需要全局 MutationObserver 兜底；但评论、懒加载图会局部动态插入。

## 2. 与 MARGIN 的对比

| 维度 | MARGIN（B站） | 本项目（MC百科，v0.2 路线） | 结论 |
|---|---|---|---|
| 架构 | MV3 + Vite bundle | 同 | ✅ 借鉴 |
| 页面模块 | `pages/*.js` 按页面拆分、动态加载 | 同 | ✅ 借鉴 |
| 数据来源 | App 私有 API + MD5 sign | DOM 抽取 | ⚠️ 改用抽取层 |
| UI | 完全自绘（flux.js + 104KB CSS） | 完全自绘 | ✅ 借鉴 |
| MAIN world 注入 | `cdn.js` 改写播放器 | 无对应场景 | ❌ 不需要 |
| 配置系统 | 40+ 项 | 精简到 12–15 项 | ✅ 借鉴思路 |
| 交互处理 | 全部自建 | 必须桥接原生（编辑/评论） | ⚠️ 本项目特有难点 |

**核心差异**：MARGIN 面对的 B 站是「接口齐全的 SPA」，可以完全抛开 DOM；MC百科是「只有 DOM 的老站」，重绘之后**原生交互会断**——这是本项目唯一需要专门设计的部分。

## 3. 架构设计（v0.2：重绘版）

### 3.1 三段式结构

```
抽取层 extract   DOM → 结构化数据（纯函数，可单测）
     ↓
数据层 store     缓存 / 跨页数据（模组→物品、物品→配方）
     ↓
渲染层 render    数据 → 自绘 UI（组件化）
     ↑
桥接层 bridge    把原生的"写操作"接回自绘 UI（编辑入口、评论、收藏）
```

### 3.2 目录结构

```
mcmod-plus/
├─ manifest.json
├─ background.js              # 设置同步、跨域抓取代理、缓存
├─ content/
│  ├─ router.js               # URL → 页面模块
│  ├─ core/
│  │  ├─ dom.js               # 安全 DOM 工具
│  │  ├─ selectors.js         # 选择器集中表（候选数组）
│  │  ├─ extract-utils.js     # 文本清洗、数字解析、时间解析
│  │  ├─ fetch.js             # fetch + DOMParser + 缓存
│  │  ├─ store.js             # chrome.storage 封装
│  │  └─ theme.js             # 设计 token 注入
│  ├─ extract/                # 每类页面一个抽取器
│  │  ├─ home.js  class.js  item.js  post.js
│  │  ├─ modlist.js  search.js  history.js  tools.js
│  ├─ render/
│  │  ├─ shell.js             # 页头/导航/页脚（全站统一）
│  │  ├─ components/          # 卡片、表格、chip、分页、空状态
│  │  ├─ pages/               # 各类页面的视图
│  │  └─ widgets/             # Cmd+K、灯箱、目录、筛选条
│  ├─ bridge/
│  │  ├─ edit-links.js        # 编辑按钮 → 原站编辑页
│  │  ├─ comments.js          # 评论区：保留原生，包一层样式
│  │  └─ login.js             # 登录态探测（读 cookie 不可行 → 探测 DOM）
│  └─ styles/
│     ├─ tokens.css           # 设计 token（颜色/间距/字号/圆角）
│     ├─ base.css             # 重置 + 基础排版
│     └─ components/*.css
├─ options/  popup/
└─ _locales/{zh_CN,en}/
```

### 3.3 三类分区（这是重绘路线的安全阀）

把页面上的每个区块按"是否可安全接管"分成三类：

| 类型 | 例子 | 处理方式 |
|---|---|---|
| **A 类：纯展示** | 简介、物品列表、合成表、教程正文、检索卡片、搜索结果 | 完全接管，自绘 |
| **B 类：站内导航/筛选** | 分类 tab、分页、筛选表单、站内链接 | 接管但**保留原生语义**：`<a href>` 真链接、`<form method="get">` 真提交，保证刷新/新标签页/分享链接仍可用 |
| **C 类：写操作** | 编辑按钮、评论框、评分、收藏、上传、登录 | **不接管**：原 DOM 原样保留，只在外层包一个容器做样式隔离 |

**失败回退**：每个页面的 `extract()` 带 schema 校验，任一必需字段缺失 → 放弃重绘，整页回退原生（白屏是绝对不允许的）。调试模式下降级原因打到 console。

### 3.4 路由

```js

  [/^\/class\/\d+\.html$/,        'class'],
  [/^\/item\/\d+\.html$/,         'item'],

  [/^\/modpack\/\d+\.html$/,      'modpack'],
  [/^\/modlist\.html$/,           'modlist'],
  [/^\/modpack\.html$/,           'modlist'],
  [/^\/class\/category\//,        'modlist'],
  [/^\/history\.html$/,           'history'],
  [/^\/class\/history\//,         'history'],

```

### 3.5 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 构建 | Vite + @crxjs/vite-plugin | 与 MARGIN 一致，MV3 支持好 |
| UI | **Preact + htm**（约 4KB） | 重绘 6 类页面状态多，需要组件化；htm 免 JSX 编译配置；比 React 轻一个量级 |
| 样式 | 原生 CSS + token 变量 | 不引入 Tailwind 运行时；便于主题切换 |
| 类型 | JSDoc + `// @ts-check` | 不上 TS 也能有检查，降低门槛 |
| i18n | chrome.i18n | MV3 原生 |

> 备选：如果不想引入任何框架，可用「原生 DOM 模板函数 + 组件目录」的写法，但 6 类页面重绘后维护成本会明显上升。

### 3.6 设计系统（重绘的前提）

先定 token，再写组件，最后拼页面——否则会变成 6 套互不一致的 UI。

- 颜色：`--mp-bg / --mp-surface / --mp-border / --mp-fg / --mp-muted / --mp-accent / --mp-warn / --mp-ok`
- 暗色：`html[data-mp-theme=dark]` 覆盖同名变量
- 字号：5 档（12/13/14/16/20），行高 1.6
- 间距：4 的倍数（4/8/12/16/24/32）
- 圆角：`--mp-radius`（默认 8px，可调 0–16）
- 组件：`Card / List / Table / Chip / Tabs / Pagination / FilterBar / Empty / Skeleton`
- 字体：优先系统字体栈，可选内置字体（不打包大字体文件）

## 4. 功能规划

### P0 · 骨架 + 设计系统

1. 构建链、manifest、router、设置页、popup。
2. 设计 token + `shell`（统一页头/导航/页脚）+ 9 个基础组件。
3. 调试面板：显示当前页面、命中模块、选择器失败项。

### P0 · 搜索（最高优先，按你的选择）

1. **全局命令面板 Cmd/Ctrl + K**
   - 任意页面唤起，输入即搜。
   - 聚合四类：模组（class）、物品（item）、教程（post）、整合包（modpack）。
   - 数据源：并行 `search.mcmod.cn/s?key=`（全文）+ `www.mcmod.cn/modlist.html?key=`（结构化），`DOMParser` 解析。
   - 结果分组 + `↑↓` 选择 + `Enter` 打开 + `Shift+Enter` 新标签。
   - 300ms 防抖、并发 2、会话缓存 5 分钟、请求失败降级为"只给站内搜索链接"。
   - 支持前缀语法：`m:` 模组、`i:` 物品、`p:` 教程、`k:` 整合包。
2. **搜索页（search.mcmod.cn）重绘**
   - 卡片：标题 + 分类色标 + 纯文本摘要（剥离 `[ban:title_menu]`、`[h1=…]`）+ 快照时间（相对格式）。
   - 关键词高亮。
   - 顶部类型筛选（全部/模组/物品/教程/整合包）→ 映射 `filter` 参数。
   - 分页保持原生 URL，可分享。

### P1 · 资料页

**物品页**：合成表表格重绘 + 工具条（复制/导出 JSON/CSV）+ 表内过滤 + 材料反查（缓存）。
**模组页**：物品分类树 + 教程卡（排序、只看精华）+ `fa-lock` 语义化 + tab 记忆。
**教程页**：悬浮目录 + 代码复制 + 图片灯箱。

### P1 · 检索页

**modlist / modpack.html**：筛选条重绘（版本/分类/加载器/排序，持久化到 URL + localStorage）、结果卡重绘（补更新时间/浏览/版本标签）、空状态与加载骨架。

### P2 · 打磨

收藏/稍后读（本地）、浏览历史、外链直达（`link.mcmod.cn/target/*` 解码）、贡献榜、bbs 可选增强。

### 明确不做

- ❌ 编辑页、登录页、个人中心接管
- ❌ 任何写操作与批量提交
- ❌ 绕过登录/权限
- ❌ 高频爬取全站建库

## 5. 技术难点与对策

| 难点 | 说明 | 对策 |
|---|---|---|
| **重绘后原生交互失效** | 编辑/评论/收藏绑定原 DOM | 三类分区（3.3）+ C 类原样保留 + 逐页验收清单 |
| DOM 脆弱 | 模板微调即失效 | `selectors.js` 候选数组 + schema 校验 + 失败整页回退 |
| 数字 id | `id="1"` 非法选择器 | 统一 `[id="1"]` 或父级 class 定位 |
| 无 API | 聚合搜索靠抓页面 | 同源 fetch + DOMParser + 缓存 + 并发限制 |
| 跨子域 | `search.` 与 `www.` 分离 | `host_permissions: https://*.mcmod.cn/*` + background 代理 |
| 内容安全 | 摘要来自用户编辑 | 只用 `textContent`；需要富文本时白名单 |
| 性能 | 物品页 12 个大表 | 按需渲染、可视区外延迟、事件委托 |
| 体积 | 6 类页面全量代码大 | 路由命中后动态 `import()`，`web_accessible_resources` 放页面模块 |
| 与原站 jQuery 冲突 | tooltip/sweetalert 全局插件 | CSS 命名空间化；不改全局函数；`unmount` 还原 |

## 7. 风险与边界

1. **站点善意**：MC百科是非营利站（关于页自述"不赚钱，靠广告和捐款仍亏损"）。插件低频、按需、可一键关闭，不做全站爬取建库。
2. **合规**：不破解、不绕过登录、不修改服务端数据；只做客户端展示层。
3. **上架**：若上架 Chrome Web Store，需要隐私政策（声明不收集用户数据）、单一用途说明、商店截图。
4. **维护**：站点改版是最大风险；选择器表 + 回退机制 + 调试面板是必需投入。
5. **工作量**：完全重绘是 v0.1 的 2–3 倍，16 个工作日是乐观估计，实际可能 3 周。

### 9.2 排版决策

只加容器类 + CSS Grid，不改 DOM、不改链接：

| 区域 | 类 | 排法 |
| --- | --- | --- |
| 主体 | `.main` → `.mp-main` | flex column，区块间距 18px |
| 分类导航条 | `.main > .nav` → `.mp-nav` | flex wrap，li 胶囊圆角 |
| 新闻区 | `.news_block` → `.mp-news` | 三栏 grid：190px / 1fr / 250px |
| 模组卡 | `.blcok_frame` → `.mp-cards`（3 个） | auto-fill minmax(132px,1fr) |
| 分类区 | `.class_category_block` → `.mp-cat`（9 个） | 两栏 grid：1fr / 240px |

明确不碰：页脚 `ul.block`、社群动态 `ul#day`、编辑动态列表、addArea 的链接语义。

### 9.3 与旧版差异

- 旧版按 `.block` 泛化 + 按 `.item` 找网格 → 把社群动态的 `ul#day` 排成了网格、给页脚加了卡片样式，视觉错乱。
- 新版只认明确的容器选择器，覆盖面小但准确。

### 9.4 已知限制

- 分类区的 `.list` 是 AJAX 加载（导出快照里是"加载中.."），卡片最终结构待抓取加载后的 DOM。
- 原站外部 CSS 未随快照保存，个别覆盖规则（float / width）用 `!important` 兜底，需真机复核。
