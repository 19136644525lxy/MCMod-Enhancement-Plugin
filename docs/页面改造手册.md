# 页面改造手册（以首页为样板）

> 沉淀「首页改版」这一轮的全部经验。之后改个人主页、物品页、模组页时按同一套流程走。
>
> 最后更新：2026-11-12（首页定稿版）

---

## 1. 先想清楚边界

每页动手前回答三个问题：

1. **哪些是「看」的，哪些是「写」的？**
   看的部分可以完全接管（简介、合成表、列表、卡片、排行）。
   写的一律不接管（编辑、评论、评分、收藏、登录），必须留在原 DOM 里，靠「切回原始视图」回去。
2. **原站 JS 会不会来抢？**
   首页的 tab、轮播、时钟都是站点 JS 驱动。接管后要给原控件加 `mp-origin-hidden`，
   否则站点脚本继续操作被隐藏的节点，可能报错或闪一下。
3. **失败时怎么退？**
   抽取失败 → `return false`，页面保持原样。**永远不要白屏。**

## 2. 分层：抽 → 渲 → 挂

```
src/content/extract/home.js      ← DOM → 纯数据对象（不碰渲染）
src/content/render/pages/home.js ← 数据 → DOM（不读 document，只读入参）
src/content/render/page-shell.js ← 公共外壳：宿主、悬浮条、恢复
src/content/widgets/*.js         ← 独立小部件（足迹、背景、设置面板）
styles/pages/home.css            ← 页面样式，全部 mp- 前缀
```

- **抽取层**只做 `document → { ok, kind, url, ... }`。好处是 `tools/test-*.js` 能直接喂真实快照，不需要浏览器。
- **渲染层**保持纯函数：`render(d)` 返回节点，不查全局。
- **挂载层**负责找锚点、插宿主、隐藏原生区块、记录还原点。

### 注入时机

```json
"content_scripts": [
  { "run_at": "document_start", "js": ["src/content/boot-splash.js"] },
  { "run_at": "document_end",    "js": [ ...23 个脚本... ] }
]
```

`document_start` 只放启动层（遮住白屏到首帧之间的空白）。
页面重绘必须在 `document_end` —— 早于站点渲染会拿不到内容。

## 3. 首页的接管清单（定稿）

| 区域 | 原生选择器 | 处理方式 |
|---|---|---|
| 顶栏 | `.top-main` | 整块隐藏，自绘 `header.mp-topbar` |
| banner 图片 | `.banner > ul#bannerMove` | **保留**，只做遮罩与上移（见 §7） |
| banner 导航 | `.banner .m_menu` | 隐藏，自绘 `.mp-bannerbar` |
| 时钟 | `.banner .nowTime` | 隐藏，自绘 `#mp-clock`（带秒 + 原站像素钟图标） |
| 内容区 | `.center > .main` | 整块隐藏，自绘 `#mp-home-host` |
| 页脚 | `.un_links` + `.under` | 隐藏，自绘 `footer.mp-footer` |
| 右下角 | —— | 自绘悬浮条 `#mp-home-fab`（增强 / 原始 / 设置） |

**原则：整块隐藏 + 整块自绘，不要在原生节点上增删改。**

半接管是最大的坑。原站 CSS 的 `float`、绝对定位、固定宽度全部依赖父子关系，
把子节点搬走或改结构，那些规则立刻全废（模组页那次「页面全乱」就是这么来的）。

唯一的例外是 banner 背景图：它本身就是独立的一层，只需要改绘制，不需要改结构。

## 4. 设计系统

### 玻璃

```css
.mp-home {
  --glass-bg: rgba(255,255,255,.55);
  --glass-bg-strong: rgba(255,255,255,.72);
  --glass-border: rgba(255,255,255,.7);
  --glass-shadow: 0 10px 40px rgba(40,32,24,.08);
  --accent: #2f6f4f;
  --radius: 20px;
}
```

### 深浅色

用 `html[data-mp-theme="dark"]` 和 `@media (prefers-color-scheme: dark)` **双写**，
后者要加 `html:not([data-mp-theme="light"])`，防止用户手动选浅色时被系统偏好覆盖。

### 动效 token（`styles/tokens.css`）

```
--mp-dur-fast .18s / --mp-dur .35s / --mp-dur-slow .58s
--mp-ease cubic-bezier(.16,1,.3,1)
--mp-ease-soft cubic-bezier(.23,1,.32,1)
--mp-ease-spring cubic-bezier(.3,1.5,.5,1)
```

**入场动画用 `backwards`，不要 `both`** —— `both` 会让 transform 一直挂在元素上，hover 的 transition 接不上。

### 主题切换

不要遮罩（深→浅像「先黑一下再亮」，比闪屏还怪）。做法是给所有会变色的面加统一过渡：

```css
transition: background-color .3s ease, border-color .3s ease,
            color .3s ease, box-shadow .3s ease;
```

注意：`background` 简写里带渐变时 `background-color` 不可过渡，必须拆成
`background-color` + `background-image` 两条属性。

## 5. 组件库 `MP.ui`

`src/content/render/components.js`，全部用 `h()` 手写，不引框架。

| 组件 | 签名 | 用途 |
|---|---|---|
| `chip(text, opts)` | 小标签 | 筛选项、统计 pill |
| `button(text, {variant, onclick})` | 按钮 | 工具栏 |
| `card(title, body)` | 卡片（`.mp-panel`） | 不要用 `.mp-card`，base.css 已占用 |
| `skeleton()` / `empty(text)` | 占位 | 加载/空态 |
| `toolbar(...)` | 工具条 | 页面顶部 |
| `dayNight({dark, class, onChange})` | 日/夜胶囊开关 | 顶栏、设置面板 |
| `paintSwitch(btn, dark)` | 上面那个的内部绘制 | —— |

SVG 图标一律用 `h('svg', ...)`，并确保走 `createElementNS`（见 §8.5）。

## 6. 数据源挖掘（本次最大收获）

MC 百科没有公开 API，但剥开 JS 能找到不少「准接口」：

### 6.1 个人中心 `center.mcmod.cn`

- 外壳是 **hash 路由单页应用**：`#/home/`、`#/rank/`、`#/favorite/`、`#/comment/`。
- 每个 tab 由 `POST /frame/{CenterHome|CenterRank|CenterComment|CenterFavoriteFold}/` 拉取，
  body `uid=<uid>&data=<json>`，返回 `{state:0, html}`。
- 例：`POST https://center.mcmod.cn/frame/CenterHome/` body `uid=829036`
  → 12KB HTML，含用户组、总编辑次数、字数、短评数、注册时间、开发模组数、最近编辑动态。
- `POST /object/UserHistoryChartData/` 恒返回 `{"state":110}`（需要登录态），**用不了**。

### 6.2 编辑历史 `www.mcmod.cn/history.html`

- `GET https://www.mcmod.cn/history.html?userid=<uid>` → 服务端直出，`.history-list li` 最近 100 条。
- `?page=` 无效；`starttime` / `endtime`（Unix 秒）**有效**，可以按月分段抓。
- 不传参数默认近 30 天窗口。
- 逻辑在 `//www.mcmod.cn/static/public/js/other/mc.history.functions.js`。

### 6.3 探测手法

1. 先看 `scripts` 里的 `*.functions.js`，函数名基本自解释（`showCenterTabPage`、`showsectime`）。
2. 用 `curl.exe --resolve <host>:443:43.254.166.30` 直连（见 §8.13）。
3. `POST` 接口用 `data=JSON` 的 body 试，返回 `state:0` 就是通了。
4. 拿到的 HTML 直接喂 jsdom 解析，和快照同样处理。

## 7. banner 处理（三次迭代的结论）

问题是：banner 是 220px 整幅大图，上面顶着顶栏、下面接着内容区，**两条硬边**。

| 迭代 | 做法 | 结果 |
|---|---|---|
| v1 | 底部 `mask-image` 淡出 | 底边柔和了，但上沿露出底色缝 |
| v2 | 顶部也淡入 | 上沿变成「图片→透明→背景」三明治，更怪 |
| v3 ✅ | **容器上移 + 加高**，顶部实心，只羽化底边 | 上沿直接压住背景，没有缝 |

```css
body.mp-home-mode .banner > ul#bannerMove {
  margin-top: -18px;
  height: 238px;
  mask-image: linear-gradient(to bottom,
    #000 0, #000 74%, rgba(0,0,0,.6) 90%, transparent 100%);
}
body.mp-home-mode .banner > ul#bannerMove li img {
  width: 100%; height: 238px;
  object-fit: cover; object-position: center top;
}
```

**关键**：`-18px` 与 `238px` 必须成对改。只改 margin 会在底部缺一块，只改 height 会在顶部留缝。

只遮 `ul#bannerMove`，不遮 `.banner` —— 导航条和时钟在 `.frame` 里是兄弟节点，
遮整个 banner 会把它们一起变半透明。

## 8. 踩过的坑（按痛苦程度排序）

### 8.1 `background-attachment: fixed` + `backdrop-filter` = 整屏闪

十几张玻璃卡各自 `backdrop-filter`，再给 body 挂 `fixed`，Windows Chrome 合成层打架，滚动整页闪。
**解法**：去掉 `fixed`，改 `background-size: 100% 1600px; background-repeat: no-repeat`。

### 8.2 `clip-path` 收尾不摘，等于整页挂一层蒙版

揭示动画 `clip-path: inset(0 0 84% round 26px) → inset(0)`，结束后 `inset(0)` 仍是裁剪层。
**解法**：`animationend` 后 `host.style.animation = 'none'`。

### 8.3 主题切换：遮罩比闪屏更难看

见 §4。用颜色 transition，不要遮罩。

### 8.4 泛选择器会误伤

`.block` 在首页同时是：模组卡、页脚 `ul`、区块容器。第一版按 `.block` 找网格，把页脚排成了卡片墙。
**解法**：只认**带语义的容器**（`.news_block`、`.blcok_frame`、`.class_category_block`），
先用 `querySelectorAll().length` 验证数量合理。

### 8.5 `document.createElement('svg')` 不渲染

`h()` 造 SVG 时 `createElement('svg')` 得到 `HTMLUnknownElement`，浏览器不画。
离线预览却正常（HTML 文本重新解析会进 SVG 命名空间）——**预览正常、真机空白**。
**解法**：`SVG_TAGS.indexOf(tag) !== -1 ? createElementNS(SVG_NS, tag) : createElement(tag)`，
并且 `class` 一律 `setAttribute('class', v)`。

### 8.6 摘要是脏的

wiki 语法残留 `[ban:title_menu]`、`[h1=简介]`；卡片里混进「编辑/删除/添加」按钮文字。
**解法**：`stripWiki()` 过一遍；`cleanText()` 克隆节点后删掉文本匹配 `编辑|删除|添加|管理|移动` 的元素。

### 8.7 无头截图不可用，只能 jsdom + Pillow

这台机器 Edge `--headless=new --screenshot` 一律挂死，不出图。
- **结构**：jsdom 加载真实快照，断言选择器数量、文本、属性
- **像素**：`python -c` + PIL 光栅化 SVG 坐标，肉眼看形状

### 8.8 快照文件名 `.html.html`

`exportSnapshot()` 里 `pathname` 已带 `.html`，再拼一次就重复。已修，但导出时仍要检查。

### 8.9 频繁刷新会触发 WAF

站长原话：「连续访问首页的一张图片上千次」。
- 插件本身不请求图片（`bg.js` 白名单 + 60 秒 30 次限流）
- **开发时**别狂刷，用离线预览看结构
- 任何轮换/刷新都做成**纯前端零请求**

### 8.10 悬浮条的按钮不能闭包旧设置

`ensureFab(settings)` 的「增强」按钮如果直接 `mount(settings)`，
用户在设置面板改过背景后，这份 settings 已过期，切回来会把新值冲掉。
**解法**：点击时 `MP.store.getSync()` 重新读一次，外面再包 `try/catch` 兜底。

### 8.11 悬浮条不能随 mount/unmount 销毁

否则点「原始」之后它自己也没了，用户回不去。
**解法**：`fabEl` 是模块级变量，`mount` 只 `ensureFab`，`unmount` 只 `syncFab`。

### 8.12 设置面板拿不到页面主题变量

面板挂在 `body` 下，不在 `.mp-home` 作用域里，`--glass-*` 取不到 → 深色下「深底 + 深字」。
**解法**：面板自带一套 `--sp-bg / --sp-ink / --sp-sub / --sp-line / --sp-hover / --sp-link`，
每个文本节点显式 `color: var(--sp-*)`。

### 8.13 本机 curl 必须 `--resolve`

`www.mcmod.cn` 解析到的节点经常抽风。直连超时就换：

```powershell
curl.exe --resolve www.mcmod.cn:443:43.254.166.30 https://www.mcmod.cn/
```

`43.254.166.30` 是海外节点，国内可用；`103.236.70.180`、`103.248.154.126`、`43.240.73.19` 视情况。

另外：PowerShell 的 `[System.IO.File]` 用**进程 CWD**，不认 `cd`，写文件要绝对路径。

### 8.14 PowerShell 正则改代码容易翻车

`-replace` 里的替换串会把 `$1`、`` `r`n ``、引号吃掉，中文还会被 GBK 读坏。
**尽量用 edit 工具改代码**，`-replace` 只用于删除整段样式这种低风险操作，改完必须 `node --check`。

## 9. 新页面改造步骤

1. **拿快照**：调试面板「导出页面 HTML」，放 `output/`。
   如果是 SPA（如个人中心），快照只有外壳，要走 §6 的接口路线。
2. **摸结构**：`tools/analyze-pages.js` 出轮廓，读一遍确定容器层级。
3. **写 extract**：`extract/xxx.js` 返回纯数据；`tools/test-extract.js` 对着真实快照断言字段。
4. **写 render**：
   - `match()` 用**精确正则**匹配路径
   - `mount(settings)` 注入 CSS、加 body 类、插宿主
   - `unmount()` 逐项还原（回归测试重点）
5. **写 CSS**：`styles/pages/xxx.css`，全 `mp-` 前缀，颜色走变量。
6. **接 manifest**：`content_scripts.js` 顺序 core → extract → widgets → render → router。
7. **跑测试**：照 `tools/test-home.js` 的模式（jsdom + 真实快照 + 断言数量）。
8. **出预览**：`tools/make-preview.js` 加一个 case。
9. **提交，不 push**（用户明确要求等他说）。

## 10. 个人主页（下一步）

### 已知

- 地址：`https://center.mcmod.cn/{uid}/`，uid 可从首页顶栏的「我的中心」链接里取（`/center.mcmod.cn/829036/`）。
- 结构是 hash SPA，主内容靠 `POST /frame/{Tab}/` 异步填充。
- 页面里有站内聊天框（`center.mcmod.cn` 自带的短消息/评论），属于 C 类写操作，**不接管**。

### 难点

| 难点 | 说明 |
|---|---|
| 异步渲染 | `document_end` 时 `#frame` 容器还是空的，要等接口回来 |
| hash 路由 | 切 tab 不刷新页面，`mount` 需要监听 `hashchange` |
| 没有快照 | 导出 HTML 只有外壳，抽取层要对着接口返回的 HTML 写 |

### 建议路线

1. 先抓 `/frame/CenterHome/`、`/frame/CenterComment/`、`/frame/CenterFavoriteFold/` 三份 HTML 存到 `output/frame-*.html`。
2. 用 jsdom 分析这三份，确定各自的容器与列表选择器。
3. `extract/center.js` 只处理「接口返回的 HTML 字符串 → 数据」，不碰页面 DOM。
4. `render/pages/center.js` 用 `MutationObserver` 等 `#frame` 出内容，或者直接接管：自己调 `/frame/` 接口，把原容器隐藏。
5. 个人主页的 tab 属于 B 类导航，接管但要保留原生链接语义。

**待确认**：个人主页里哪些块是用户自己的（可编辑），哪些是别人的（只读）——
如果同一套模板要同时服务「自己的主页」和「别人的主页」，编辑按钮这类要按 uid 判断。

## 12. 一句总结

> 用「整块隐藏 + 整块自绘 + 可完整还原」换视觉自由，
> 用「抽取层纯数据 + jsdom 断言」换回归安全，
> 用「纯前端零请求」换不被 WAF 找麻烦。

## 全局约定：日夜开关

用户明确要求（2026-11-12）：**日夜开关以后每个页面都要有**，不是个人主页专属。

- 组件：`MP.ui.dayNight({ dark, class, onChange })`，定义在 `src/content/render/components.js`，来自 MARGIN 的 `gn()` 复刻。
- 样式：`styles/day-night.css`（类名 `mp-ts-*`）。
- 已接入：
  - 首页：`home.js` 的 `themeSwitch()`，顶栏内（`.mp-theme-switch`）。
  - 个人主页：`center.js` 的 `ensureDayNight()`，插在 `.header-right` 之前，id `mp-daynight`。
- 其余页面（item / klass / modpack / category / search）接入时，优先查 `.top-main .info`，插在 `.info` 之前；查不到再退回 `body` 右下角，避免挡住内容。
- 切换逻辑统一走 `MP.theme.apply({ theme })` + `MP.store.setSync({ theme })`，不要各写一套。

## 13. 个人主页与主题系统（2026-11-13 定稿）

> 第 10 节写于开工前，这一节是做完之后的实际结论，以本节为准。

### 13.1 页面结构

个人主页是 hash 路由 SPA：`#/home/`、`#/rank/`、`#/favorite/`、`#/comment/`、`#/task/`、`#/item/`、`#/card/`、`#/setting/`。

每个 tab 的内容由 `POST https://center.mcmod.cn/frame/{Tab}/` 拉 JSON 片段填进对应的 `#center-page-*`，所以：

- **不要试图导出 HTML 做离线分析**：导出的只是外壳，tab 内容全是空的。
- 抓片段要带四个头，缺一个就返回 0 字节：
  `Referer: https://center.mcmod.cn/{uid}/`、`Origin`、`X-Requested-With: XMLHttpRequest`、`Content-Type: application/x-www-form-urlencoded`，body `uid={uid}&data=%7B%7D`。
- 匿名能拿到的只有 `CenterHome` / `CenterRank` / `CenterComment` / `CenterSetting`（部分）。`CenterTask` 和 `CenterCard` 返回 `{"state":0,"html":""}`，`CenterFavoriteSoltList` 返回 `{"state":217}`（要登录）——这三个只能靠截图 + 猜类名，或者让用户贴 DevTools。

### 13.2 主题变量

`styles/pages/center.css` 顶部一组 `--c-*`：

| 变量 | 浅色 | 深色 |
|---|---|---|
| `--c-ink` | `#26231f` | `#e6e1d8` |
| `--c-ink-2` | `#55504a` | `#b9b2a8` |
| `--c-ink-3` | `#857f75` | `#8f887d` |
| `--c-card` | `rgba(255,255,255,.55)` | `rgba(26,25,22,.52)` |
| `--c-card-soft` | `rgba(255,255,255,.4)` | `rgba(26,25,22,.38)` |
| `--c-hair` | `rgba(38,35,31,.09)` | `rgba(255,255,255,.1)` |

**关键原则**：卡片底色 `.55` 而不是 `.88`。太不透明就看不出底下是背景图，页面会退化成「一堆白卡叠在灰底上」。真要加不透明度，用 `backdrop-filter: blur()` 补偿，不要靠提高 alpha。

### 13.3 主题切换的平滑过渡（重要）

**普通 CSS 变量不能参与 transition**。如果背景由「`background-color` + `radial-gradient`」组成，只给颜色加过渡，会得到「渐变已经变暗、底色还在浅色」的中间态——用户看到的就是「半暗半白」。

正确做法：用 `@property` 把颜色变量注册成可插值类型，让渐变和底色由同一组缓动驱动。

```css
/* styles/tokens.css */
@property --mp-bg-base { syntax: '<color>'; inherits: true; initial-value: #f3f1ec; }
@property --mp-spot-a  { syntax: '<color>'; inherits: true; initial-value: rgba(87,185,138,.16); }
@property --mp-spot-b  { syntax: '<color>'; inherits: true; initial-value: rgba(214,168,96,.14); }
@property --mp-spot-c  { syntax: '<color>'; inherits: true; initial-value: rgba(120,140,200,.1); }
```

```css
/* styles/pages/home.css */
body.mp-home-mode {
  --mp-bg-base: #f3f1ec;
  --mp-spot-a: rgba(87,185,138,.16);
  /* … */
  background-color: var(--mp-bg-base);
  background-image:
    radial-gradient(1200px 600px at 15% -10%, var(--mp-spot-a), transparent 60%),
    radial-gradient(900px 500px at 95% 5%,  var(--mp-spot-b), transparent 55%),
    radial-gradient(700px 600px at 50% 100%, var(--mp-spot-c), transparent 60%);
  transition: --mp-bg-base .34s ease, --mp-spot-a .34s ease,
              --mp-spot-b .34s ease, --mp-spot-c .34s ease;
}
html[data-mp-theme="dark"] body.mp-home-mode {
  --mp-bg-base: #14130f;
  --mp-spot-a: rgba(87,185,138,.14);
  /* … */
}
```

翻 `data-mp-theme` 就完事，`MP.theme.apply()` 里不要再做任何「冻结过渡两帧」之类的补丁。

**反例（已废弃）**：给 `html` 加一个类让所有元素 `transition: none`，两个 rAF 后再移除。它确实没有中间态了，但变成硬切，用户立刻反馈「太不美观」。

### 13.4 深色兜底与特异性

原站很多地方把颜色写死成 `#222` / `#000`，深色主题下就是黑字黑底。两条通用兜底：

```css
html[data-mp-theme="dark"] body.mp-center-mode .tab-content,
html[data-mp-theme="dark"] body.mp-center-mode .tab-content *:not(img):not(svg):not(path):not(use) {
  color: #e6e1d8 !important;
}
html[data-mp-theme="dark"] body.mp-center-mode .tab-content a,
html[data-mp-theme="dark"] body.mp-center-mode .tab-content a * { color: #7ed0a5 !important; }
```

**踩过的最大一个坑：`!important` 不保证赢**。双方都带 `!important` 时，浏览器比的是**特异性**。

```css
/* 原站：0,4,1 */
.center-main.favorite .favorite-slot-ul li { border-right: 10px solid #FFF; }
/* 我第一版：0,2,1 —— 加 !important 也没用，照样输 */
body.mp-center-mode .favorite-slot-ul li { border-right: 10px solid transparent !important; }
/* 修法：塞一个 id 进去，变成 1,4,1 */
body.mp-center-mode #center-page-favorite .center-main.favorite .favorite-slot-ul li { … !important }
```

排查顺序：先看 DevTools 里那条规则有没有被划掉 → 被划掉就是权重输，加 id 或复制原站完整选择器。

### 13.6 页脚 logo

`footer img.logo` 原图是 `logo_dynamic.gif`（265×172，36 帧）。处理流程在 `tools/clean-logo.py`：

1. 逐帧读 RGBA；
2. 找「自己可见、四邻有透明像素」的边缘像素；
3. 其中 `R/G/B > 200` 的（白渣）alpha 设为 0；
4. 存成 WebP 动画（保留 36 帧 / 时长 / 循环）。

产物 `assets/logo_dynamic.webp`（137KB，比原 GIF 的 142KB 还小）。`center.js` 的 `swapFooterLogo()` 在 `mark()` 里把 `src` 换掉。
