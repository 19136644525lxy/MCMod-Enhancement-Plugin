# 页面改造手册（以首页为样板）

> 这份文档沉淀的是「首页改版」这一轮的全部经验。
> 之后改物品页、模组页、检索页、分类页时，按同一套流程走，能省掉大部分返工。
>
> 最后更新：2026-11-12

---

## 1. 先想清楚边界

每一页动手前，先回答三个问题：

1. **这一页哪些是「看」的，哪些是「写」的？**
   看的部分可以完全接管（简介、合成表、列表、卡片、排行）。
   写的部分一律不接管（编辑、评论、评分、收藏、登录），它们必须留在原 DOM 里，靠「切回原始视图」回去。
2. **原站的 JS 会不会来抢？**
   首页的 tab、轮播、时钟都是站点 JS 驱动的。接管后要给原控件加 `mp-origin-hidden`，
   否则站点脚本继续操作被隐藏的节点，可能报错或闪一下。
3. **失败时怎么退？**
   抽取失败 → 直接 `return false`，让页面保持原样。**永远不要出现白屏**。

## 2. 分层：抽 → 渲 → 挂

页面模块统一三段，文件名固定：

```
src/content/extract/home.js     ← DOM → 纯数据对象（不碰渲染）
src/content/render/pages/home.js ← 数据 → DOM（不读 document，只读入参）
src/content/render/page-shell.js ← 公共外壳：宿主、悬浮条、恢复
```

**抽取层**只做一件事：把 `document` 变成 `{ ok, kind, url, ... }` 这种可测试的对象。
好处是 `tools/test-*.js` 可以直接喂真实快照，不需要跑浏览器。

**渲染层**保持纯函数风格：`render(d)` 返回一个节点，不查询全局。

**挂载层**负责：
- 找到锚点（`anchor`），在它前面插入宿主 `#mp-home-host`
- 给原生区块加 `mp-origin-hidden`
- 记住哪些节点被隐藏/移动，`unmount()` 时逐个还原

## 3. 首页的接管清单

按「改什么」分类，后续页面照抄这个分类法：

| 区域 | 原生选择器 | 处理方式 |
|---|---|---|
| 顶栏 | `.top-main` | 整块隐藏，自绘 `header.mp-topbar` |
| banner 导航 | `.banner .m_menu` | 隐藏，自绘 `.mp-bannerbar` |
| 时钟 | `.banner .nowTime` | 隐藏，自绘 `#mp-clock`（带秒） |
| 内容区 | `.center > .main` | 整块隐藏，自绘 `#mp-home-host` |
| 页脚 | `.un_links` + `.under` | 隐藏，自绘 `footer.mp-footer` |
| 保留 | `.banner` 背景图 | 不动 |

原则：**整块隐藏 + 整块自绘**，不要在原生节点上做增删改。
半接管是最大的坑——原站 CSS 的 `float`、绝对定位、固定宽度全部依赖父子关系，
你把子节点搬走或改结构，那些规则就全废了。（模组页那次「页面全乱」就是这么来的。）

## 4. 设计系统

所有颜色、圆角、阴影、动效都从 CSS 变量走，不要写死：

```css
.mp-home {
  --glass-bg: rgba(255,255,255,.55);
  --glass-bg-strong: rgba(255,255,255,.72);
  --glass-border: rgba(255,255,255,.7);
  --accent: #2f6f4f;
  --radius: 20px;
}
```

深浅色两份值，用 `html[data-mp-theme="dark"]` 和 `@media (prefers-color-scheme: dark)` 双写，
后者用 `html:not([data-mp-theme="light"])` 防止用户手动选浅色时被系统偏好覆盖。

动效 token 在 `styles/tokens.css`：

```
--mp-dur-fast .18s / --mp-dur .35s / --mp-dur-slow .58s
--mp-ease cubic-bezier(.16,1,.3,1)
```

入场动画的原则：**`backwards` 不要 `both`**，否则动画结束后 transform 还挂着，hover 的 transition 接不上。

## 5. 踩过的坑（按痛苦程度排序）

### 5.1 `background-attachment: fixed` + `backdrop-filter` = 整屏闪

首页有十几张玻璃卡，每张都 `backdrop-filter`。再给 `body` 挂 `background-attachment: fixed`，
Windows Chrome 的合成层会打架，滚动时整页闪。

**解法**：去掉 `fixed`，改成 `background-size: 100% 1600px; background-repeat: no-repeat`，光斑只铺在文档顶部。

### 5.2 `clip-path` 收尾不摘，等于整页挂一层蒙版

揭示动画用 `clip-path: inset(0 0 84% round 26px) → inset(0)`。
动画结束后 `inset(0)` 仍然是个裁剪层，和毛玻璃叠加又闪。

**解法**：`animationend` 后 `host.style.animation = 'none'`，把动画属性整个摘掉。

### 5.3 主题切换：遮罩比闪屏更难看

试过用全屏遮罩先盖住再揭开。结果深→浅时像「先黑一下再亮」，比原来的闪屏还怪。

**解法**：不要遮罩。把所有会变色的面统一加 `transition: background-color .3s, border-color .3s, color .3s`，
属性一换颜色自己渐变。注意 `background` 简写里带渐变时 `background-color` 不可过渡，
必须拆成 `background-color` + `background-image` 两条。

### 5.4 泛选择器会误伤

`.block` 在首页同时是：模组卡、页脚 `ul`、区块容器。
第一版按 `.block` 找网格，结果把页脚排成了卡片墙。

**解法**：只认**带语义的容器**（`.news_block`、`.blcok_frame`、`.class_category_block`），
并且先在小样本上跑 `querySelectorAll().length` 验证数量合理。

### 5.5 `document.createElement('svg')` 不渲染

用 `h()` 造 SVG 时，`createElement('svg')` 得到的是 `HTMLUnknownElement`，浏览器不画。
而离线预览页因为是 HTML 文本重新解析，`<svg>` 会走 HTML 解析器进 SVG 命名空间，**预览正常、真机空白**。

**解法**：`SVG_TAGS.indexOf(tag) !== -1 ? document.createElementNS(SVG_NS, tag) : createElement(tag)`，
并且 `class` 一律 `setAttribute('class', v)`（SVG 的 `className` 是对象不是字符串）。

### 5.6 摘要是脏的

站点会把 wiki 语法残留在文本里：`[ban:title_menu]`、`[h1=简介]`。
卡片里还会混进「编辑 / 删除 / 添加」这类按钮文字。

**解法**：`stripWiki()` 过一遍；`cleanText()` 克隆节点后删掉文本匹配 `编辑|删除|添加|管理|移动` 的元素。

### 5.7 无头截图不可用，只能靠 jsdom + Pillow

这台机器上 Edge `--headless=new --screenshot` 会挂死，不出图。
所以视觉自检只能：
- **结构**：jsdom 加载真实快照，断言选择器数量、文本、属性
- **像素**：`python -c` 用 PIL 把 SVG 坐标光栅化，肉眼看形状对不对

### 5.8 快照文件名会 `.html.html`

`exportSnapshot()` 里 `pathname` 已经带 `.html`，再拼 `.html` 就重复。
已修（`path.replace(/\.html?$/i, '')`），但导出时仍要检查。

### 5.9 频繁刷新首页会触发 WAF

站长的原话是「连续访问首页的一张图片上千次」。
插件本身不请求图片，但**开发时反复刷新**会。所以：

- 改完代码不要狂刷，用离线预览 `output/preview-*.html` 看结构
- 插件里任何轮换/刷新都做成**纯前端零请求**
- `bg.js` 有白名单 + 60 秒 30 次限流

## 6. 新页面改造的步骤（照做）

1. 让用户导出该页快照（调试面板「导出页面 HTML」），放到 `output/`。
2. 用 `tools/analyze-pages.js` 生成结构轮廓，读一遍确定容器层级。
3. 写 `extract/xxx.js`，返回纯数据；用 `tools/test-extract.js` 对着真实快照断言字段。
4. 写 `render/pages/xxx.js`：
   - `match()` 用**精确正则**匹配路径
   - `mount(settings)` 里注入 CSS、加 body 类、插宿主
   - `unmount()` 逐项还原（这是回归测试的重点）
5. CSS 放 `styles/pages/xxx.css`，全部 `mp-` 前缀，颜色走变量。
6. 加进 `manifest.json` 的 `content_scripts.js`（顺序：core → extract → widgets → render → router）。
7. 跑 `tools/test-home.js` 那套模式：jsdom + 真实快照 + 断言数量。
8. 生成离线预览 `tools/make-preview.js`，交给用户看。
9. 提交。**不要 push**（用户明确要求等他说）。

## 8. 一句总结

> 用「整块隐藏 + 整块自绘 + 可完整还原」换视觉自由，
> 用「抽取层纯数据 + jsdom 断言」换回归安全，
> 用「纯前端零请求」换不被 WAF 找麻烦。
